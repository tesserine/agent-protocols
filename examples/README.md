# Worked Examples

Two real protocols from the
[groundwork](https://github.com/tesserine/groundwork) methodology
(v0.3.0-rc.1), re-expressed in the canonical model. They are the proof that
the form carries real wisdom cleanly: every sentence of the source protocols
has a home here — in a one-line frontmatter field or an anchored body
section — and the structure that previously lived in a separate, drifting
TOML graph now lives in the same file as the prose it routes.

Each directory mirrors the reference runtime's layout convention: the
canonical model **is** `protocols/{name}/PROTOCOL.md`. The `views/`
directories beside them are derived — generated by
[`tools/project.py`](../tools/project.py), regenerable at any time, and
never edited by hand.

## [review](review/PROTOCOL.md)

The scoped pipeline's independent-judgment gate. Demonstrates:

- the **contract spine** — a precondition of required and optional
  artifacts, and a postcondition that is a typed disposition group
  (exactly one of `change-approved` or `change-needs-revision`);
- **branch on typed outcome** — the `review-disposition` group, projected as
  a choice pseudostate;
- **delegation** — the inspection step applies the `code-review` skill;
- the **inter-protocol boundary**, precisely: review has *no* intra-protocol
  loop. Both outcomes exit the protocol; the revision loop
  (needs-revision → submit → new proposal → re-review) belongs to the
  computed inter-protocol graph. Being exact about which graph owns the loop
  is part of the example's value.

## [verify](verify/PROTOCOL.md)

The completion gate. Demonstrates:

- the **feedback edge** — the loop the source prose carries ("the gate
  re-runs fresh from step 2") but the superseded TOML graph omitted
  entirely. `repair-increment` yields `increment-fix`, which `run-fresh`
  declares as a feedback need: the loop is a declared data dependency, not a
  hand-drawn arrow;
- **faithful loop semantics.** The source's "fresh" is a state-discard rule:
  a repair makes all earlier output stale. The data-flow model carries this
  exactly — when `run-fresh` re-yields `verification-output`, everything
  downstream re-derives from the new instance; nothing stale survives the
  loop by construction. Per-instance versioning of artifacts across rounds
  is runtime-owned and out of the model's scope;
- **a modeling promotion.** The source prose embeds the repair moment inside
  its step 3 ("stop and invoke `debug`… then the gate re-runs"); as a graph
  it is a step of its own. The model makes the implicit node explicit —
  six steps where the prose numbered five — and the prose wisdom moved with
  it, undivided.

## Provenance and drift

The source protocols each existed as two files: prose
(`protocols/{name}/PROTOCOL.md`) and a TOML graph
(`workflow-contracts/{name}.toml`). At the time of adaptation the pairs had
drifted — review's prose had four steps and four corruption modes beside a
two-node graph with three differently worded corruption modes; verify's
prose loop was absent from its graph. The canonical model subsumes both
files; the correspondence table lives in the
[Tesserine binding](../bindings/tesserine.md#succession-workflow-contracts).
